## 一、成品开场：你能产出什么

前几讲你得到了三样东西：
- 一张**带置信度的图**（第 01 讲）：节点=设备、边=管线、属性=置信度。
- 一套**软硬约束**（第 02–04 讲）：泵有进有出、换热器两侧连通、仪表是支路、管径变化匹配阀件……
- 一人一份**碎片观察**：张三说"罐底接泵"，李四说"泵出口朝换热器方向"，王五说"换热器有根管接外输"。

这一讲把它们**喂给一个求解器**。这段脚本（`scripts/lec11-01_topology_search.py`）的输出就是你能交付的中间产品：

```
  total valid solutions: 18
  Top-5:
    #1  score=210  edges=[0,1,2]   ← 最优
    #2  score=145  edges=[0,5]     ← 泵直送外输，换热器闲置
    #3  score=140  edges=[0,1]     ← 换热器出口无去向
    #4  score=135  edges=[0,3]     ← 有回流见过给换热器
```

你立刻能看出：**最优解（路径 T→P→E→S）不是唯一答案**——还有 17 个同样合法但分数更低的候选。而且没有一条边在所有 top-10 解里都出现（稳定边=无），这意味着靠现有信息无法锁定唯一拓扑。**这个结论本身就比"猜一个"有价值得多。**

## 二、把碎片"形式化"：端口、候选边、得分、约束

### 2.1 定义"端口"

三人观察里的每一个设备，拆成它可能用于连接的"口"。实体可以有多个端口：

| 设备 | 端口 | 含义 |
|---|---|---|
| T-101 罐 | `T_bot` | 底部出料口 |
| P-101 泵 | `P_in` | 吸入侧（入口） |
| P-101 泵 | `P_out` | 排出侧（出口） |
| E-101 换热器 | `E_in` | 工艺侧入口 |
| E-101 换热器 | `E_out` | 工艺侧出口 |
| 外输（Stream） | `S_in` | 接收入口 |

> **为什么要拆端口而不直接用"设备"做节点？** 因为很多设备有多个口（泵有进/出，换热器有两套进出口），用端口才能写出"每个口最多接一根管"这样的约束。第 01 讲的简单约束图在这里升级为**端口级约束图**。

### 2.2 生成候选边

对每一段"看起来可能相连"的管线段，生成一条候选边，附上**置信度得分**（score，0–100，越高代表观察证据越强）。这是求解之前的"人工/半自动推理"步骤——靠第 02–04 讲的物理常识和空间位置判断哪些连接是可能的。

**本讲示例的 7 条候选边**：

| # | 端点 | 端点 | 得分 | 含义 |
|---|---|---|---|---|
| 0 | `T_bot` | `P_in` | 70 | 罐底→泵入口，高置信观察 |
| 1 | `P_out` | `E_in` | 50 | 泵出口→换热器入口，中置信 |
| 2 | `E_out` | `S_in` | 50 | 换热器出口→外输，中置信 |
| 3 | `E_out` | `P_out` | 45 | 疑似回流，低置信 |
| 4 | `E_out` | `T_bot` | 40 | 疑似旁路，低置信 |
| 5 | `P_out` | `S_in` | 55 | 泵直接送外输，替代路径 |
| 6 | `T_bot` | `S_in` | 30 | 罐直接送外输，弱观察 |

> **得分怎么定？** 本讲先手工定（展示原理）；真正作业中可以：① 用空间距离和端口相容性自动生成候选并打分；② 人工调整置信度（高/中/低对应 70–100/40–65/10–35）。

### 2.3 约束：硬 vs 软

**硬约束**（必须满足，违反则解无效）：

```
每个端口最多被一条候选边使用（图文论里的"度数 ≤ 1"）
```

这是唯一写在 `is_valid()` 里的硬约束。它的物理含义：一根管不能同时接两处、一个口也不会同时接两根管。

**软约束**（不要求必须满足，但满足时加分，使更合理的拓扑得分更高）：

| 软约束 | 加分 | 物理来源 |
|---|---|---|
| 泵 P-101 的吸入口和排出口都连通 | +20 | 第 03 讲：泵有进有出是工作前提 |
| 换热器 E-101 的工艺入口和出口都连通 | +20 | 第 05 讲预告：换热器两侧流体各两端口 |

软约束加在 `tot_score()` 的目标函数里，不是硬性排除。这使得求解器能比较"完全连通的合理拓扑"和"部分断开的存疑拓扑"，并选出后者**仅当观察证据极其不足时**。

## 三、求解：穷举 vs CP-SAT

### 3.1 穷举（本讲用）

对于 $n$ 条候选边，最多有 $2^n$ 种组合。$n=7$ 时只有 128 种——直接枚举所有组合、检查硬约束、算总分，最快。

```python
valid = []
for mask in range(1 << nvars):
    if is_valid(mask):
        valid.append((mask, score(mask)))
valid.sort(key=lambda x: -x[1])  # 高分在前
```

**适用于**：$n \lesssim 25$（$2^{25}\approx 3300$ 万，仍是可枚举的，但已到几秒级别）。**本课脚本中穷举到 $2^7=128$ 是 0.13 秒终结。**

### 3.2 OR-Tools CP-SAT（大规模推荐）

当候选边 $n > 30$ 时，$2^n$ 天文数字，必须用约束求解器（如 **OR-Tools CP-SAT**：Google 开源的整数规划求解器，专为布尔/整数约束优化设计）。用 CP-SAT 建模等价于上面的穷举但更高效：

```python
from ortools.sat.python import cp_model
model = cp_model.CpModel()
x = [model.NewBoolVar(f"x{i}") for i in range(n)]
model.Maximize(sum(score_i * x[i] for i in range(n)))

# 硬约束：每个端口最多一条
for port_incident in port_groups:
    model.Add(sum(x[i] for i in port_incident) <= 1)

# 软约束作为目标函数的一部分已包含
solver = cp_model.CpSolver()
solver.Solve(model)
```

CP-SAT 可以处理 $n=10^3–10^4$ 级别的候选边，还能用**排除约束**枚举前 k 个解，和你本讲学到的穷举逻辑完全相同。

> **⚠ 本机 ortools 的段错误**：本课的 Windows 环境中，ortools 9.15 的 CP-SAT 原生库在 `solver.Solve()` 时触发段错误（`0xC0000005`），原因不明（可能是 ortools wheel 与某系统库冲突）。本课脚本已用等价穷举替代。**如果在你电脑上 ortools 能正常工作（大多数 Linux/Mac/WSL 可），请用 CP-SAT 版**；否则穷举 >=25 个变量也是一个可接受的教学替代方案。

## 四、K-best 枚举：只看最优解会错过什么

只输出最优解 #1（T→P→E→S，score=210），你会以为"这就是唯一答案"。但看 #2–#10 就会发现完全不同的拓扑也合法：

| # | 分数 | 选中的边 | 含义（拓扑形态） |
|---|---|---|---|
| 1 | **210** | `[0,1,2]` | T→P→E→S 连成一条直线（最合理） |
| 2 | **145** | `[0,5]` | T→P→S，跳过换热器 |
| 3 | **140** | `[0,1]` | T→P→E，换热器出口没去向 |
| 4 | **135** | `[0,3]` | T→P, 且 E→P 回流（环） |
| 5 | **120** | `[0,2]` | T→P, E→S，两段孤立 |
| 6 | **120** | `[1,2]` | P→E→S，罐没参与 |
| 7 | **110** | `[1,4]` | P→E, E→T 旁路 |
| 8 | **95** | `[4,5]` | 仅旁路+泵直送外输 |
| 9 | **80** | `[1,6]` | P→E, T→S 孤立 |
| 10 | **75** | `[3,6]` | T→S, E→P 回流 |

**关键观察**：
- #2 和 #6 都忽略了某个设备不连通——软约束扣了 20 分（泵或换热器单侧不通），但仍合法。
- **没有哪条边在前 3 个解里同时出现**，意味着每一条候选边都有被排除的候选解。

这个"多解"事实是 chat 素材里说"不可能唯一"的数学呈现。**看 k-best 不是为了换个答案，而是为了理解信息缺口有多大。**

## 五、稳定边频率：哪些连接可靠、哪些只是凑对

把 top-K 个解里**每一条候选边出现的次数**统计出来：

```
STABLE(100%): []    ← 没有一条边在所有 top-10 解里都出现
UNSTABLE:   
  0: T_bot->P_in    fr=5/10    ← 最稳定（出现 5 次）
  1: P_out->E_in    fr=5/10
  2: E_out->S_in    fr=3/10
  3: E_out->P_out   fr=2/10
  4: E_out->T_bot   fr=2/10
  5: P_out->S_in    fr=2/10  
  6: T_bot->S_in    fr=2/10
```

**解读方式**：
- 没有边达到 100% → **本例无法唯一确定拓扑**。
- 边 0 和 1 出现 5/10（50%）= 相对较稳定但非决定。
- 由于本例候选边数少且约束弱（唯一的硬约束是"端口≤1"），多解是预期结果——这不说明方法有问题，**正说明了信息不足以收敛**。

> **如果你的作业数据能得到几个 100% 稳定边**：恭喜，那些边就是"报告里能画实线的确定连接"。如果你遇到和本例一样的情况（全是不稳定）——你就诚实写"当前观察无法唯一确定拓扑，以下为可能性排序，建议补充观察。"——这正是 chat 素材里"不强行下结论"的工程伦理。

## 六、敏感性分析：结论靠不靠谱？

把最关键的观察（边 0，得分 70 的那条"罐底→泵"）删掉，把它的得分降为 0，重新求解。

**实测结果**：最优解仍然是 `[0,1,2]`，即**删除这条观察后，同一套边仍被选中**（只是边 0 的得分贡献从 70 变成 0，总分从 210 降到 140）。

含义：**本例的结论对这条观察是稳健的（robust）**——即使你没有看到罐底到泵的明确证据，泵和换热器连通、换热器到外输连通这些观察也足够支撑相同的拓扑。如果相反情况发生（删一条观察就大幅改变拓扑），说明结论**脆弱（fragile）**，你更应该强调不确定性而不是给出唯一答案。

## 七、本讲小结

- **形式化**：观察碎片→端口+候选边+置信度得分+硬软约束。
- **硬约束**（必须满足）：端口连接数 ≤ 1。
- **软约束**（加分项）：泵双口连通 +20、换热器双口连通 +20（来自第 02–04 讲，更多软约束可随设备知识逐级添加）。
- **求解**：小规模($n\lesssim25$) 穷举，大规模用 OR-Tools CP-SAT。
- **K-best 枚举**：不止看最优解，看前 K 个解的分布判断信息缺口。
- **稳定边频率**：100% = 报告里画实线；不 100% = 画虚线/标注不确定。
- **敏感性分析**：删一条观察，结论变不変？变 = 脆弱，强调不确定性。
- $\text{次}$ 8 个合法解群演示了"信息不足时不会收敛到唯一解"的 ill-posed 性质。

<details><summary>參考答案</summary>

**硬約束**（必須滿足，用 `model.Add(...)` 或 `if not: return False`）：
1. 每個端口最多被一條候選邊使用。（鐵律：一根管不能同時接兩處。）
2. （可選，若觀察充足）某條觀察確定已確認連接 → 強制選中（`Add(x_i == 1)`）。

**軟約束**（加分項，用在目標函數中，每條 +15~+20 分）：
3. 泵 P-101 的 P_in 和 P_out 都 ≥1 → +20 分。（泵需要進出口才能工作。）
4. 換熱器 E-101 的 E_in 和 E_out 都 ≥1 → +20 分。（工藝側循環流過，兩邊都得接。）
5. 排出口傾向於接到低點而非高點 → +10 分。（位頭低利於重力自流，第 02 講。）
6. 泵的排出側應當有下游客戶（不憋死）→ +10 分。（但不能硬性排除「暫時無去向」的尾部設備。）

（上面 5 和 6 在本講演示數據裏沒有用到，但在真實作業中可以有——這就是你從第 02–04 講裏提取的軟約束庫。）
