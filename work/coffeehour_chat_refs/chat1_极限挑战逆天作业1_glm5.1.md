- 地面有易绊倒物；
- 需要上窜下跳、跨越管道或踩踏设备才能观察；

## 二、一个半小时内不要试图完整还原

采用“**分区—编号—连接置信度**”方法。

### 1. 先画总体布局

拿纸画一个简单平面或立面草图，不追求比例，只标：

- 设备位置；
- 楼梯、平台和通道；
- 主要管道走向；
- 阀门、泵、储罐、换热器、仪表等；
- 入口、出口、排放点；
- 你无法观察到的区域。

先建立坐标，例如：

- T-101：储罐；
- P-101：泵；
- V-101：阀门；
- E-101：换热器；
- L-101：液位计；
- PI-101：压力表。

不要一开始纠结设备的真实名称，先用“设备A”“管线B”也可以。

### 2. 给每一段管线编号

每看到一段管道就记录：

| 编号 | 起点 | 终点 | 方向 | 附件 | 置信度 | 备注 |
|---|---|---|---|---|---|---|
| L-101 | T-101附近 | P-101附近 | 不明 | V-101 | 中 | 中间被遮挡 |
| L-102 | P-101出口 | E-101入口 | 推测 | PI-101 | 低 | 可能为模型假管 |
| L-103 | E-101出口 | 排放口 | 不明 | V-102 | 低 | 连接处不可见 |

置信度建议分为：

- **高**：两端都能直接看到，连接连续且无遮挡；
- **中**：一端可见，另一端依据走向或附件推测；
- **低**：只凭外观、位置或工艺常识判断；
- **未知**：无法确认，不要强行补全。

### 3. 用不同线型表达事实与推测

- 实线：现场直接确认；
- 虚线：根据走向推测；
- 点划线：可能的替代路径；
- 叉号：断开、封堵或疑似假管；
- 问号：连接关系未确认；
- 阴影：无法进入或无法观察区域。

这样即使拓扑没有完全还原，报告也能体现你的辨识过程是严谨的。

## 三、现场优先记录什么

在时间有限时，优先级如下：

1. **设备编号和功能可能性**；
2. **主要物料流向**；
3. **泵、阀门和仪表的位置**；
4. **管线的起点和终点**；
5. **异常结构和无法确认的部分**；
6. 管径、材质、颜色等次要信息。

每个设备至少记录：

- 外形；
- 可能功能；
- 连接管线；
- 进出口；
- 附属阀门和仪表；
- 观察依据；
- 不确定点。

例如：

> 设备A：立式圆筒容器，顶部连接至少两条管线，底部疑似有排液口。根据其容积和位置，可能承担储存或缓冲功能，但无法仅凭现场外观确认其实际用途。

## 四、不要被“假的管道”带偏

对于明显可疑的管道，记录其证据，而不是擅自判断：

- 是否有连续支撑；
- 两端是否真正接入设备；
- 是否有法兰、螺纹、焊口或阀门；
- 管径是否突然变化；
- 是否存在断口、封堵或胶带；
- 是否与其他管道形成不合理交叉；
- 是否可能只是展示用外壳或模型件。

报告中可写：

> 该管线外观上具有工艺管道特征，但现场未能确认其两端与设备的实际连通关系，因此不将其纳入确定拓扑，仅作为疑似支路保留。

## 1. 把问题形式化

把系统表示成图：

- **节点**：罐、泵、换热器、阀门、三通、仪表、排放口、盲端；
- **边**：管线片段；
- **属性**：方向、管径、介质猜测、连接类型、是否可见、置信度、是否疑似假管；
- **约束**：某段管线必须接到某节点、某设备有几个入口/出口、泵只能从入口流向出口等。

不要一开始就只保留一张图，而是保留：

1. 已确认拓扑；
2. 候选连接；
3. 明确不可能的连接；
4. 尚未观测的连接。

这比强行输出一个“完整答案”可靠。

## 2. 最适合的算法路线

### 第一层：数据整理和实体对齐

先解决三个人记录中的“同一个东西被叫成不同名字”：

- 统一设备编号；
- 统一空间位置；
- 统一管线编号；
- 合并重复观察；
- 标记冲突。

这一步通常比算法更重要。

可以用：

- 坐标或区域匹配；
- 设备类型匹配；
- 连接端数量匹配；
- 管径、颜色、走向等属性匹配；
- 人工确认低置信度匹配。

如果要自动化，可用相似度评分，而不是直接用大模型拍板。

```python
score = (
    0.35 * location_similarity +
    0.25 * type_similarity +
    0.20 * port_similarity +
    0.20 * visual_similarity
)
```

### 第二层：候选边生成

对于每个管线端点，只生成物理上可能的连接：

- 空间距离在阈值内；
- 高程差合理；
- 管径或接口规格相容；
- 方向不矛盾；
- 中间没有不可穿越结构；
- 不违反已知的设备端口类型。

这一步叫 candidate generation。不要让每个端点连接任意节点，否则组合数量会爆炸。

### 第三层：约束满足或整数规划

如果你们需要从候选连接中选出一组最可能的拓扑，最合适的是：

- **CSP**：约束满足问题；
- **SAT/SMT**：逻辑约束多时；
- **MILP/CP-SAT**：既有硬约束，又要最大化置信度时。

工程上我更推荐 **OR-Tools CP-SAT**，因为它适合“是否连接”“是否为假管”这类布尔变量，并且可以加入评分函数。

定义变量：

```text
x[i,j] = 管线端点 i 是否连接到节点 j
z[k]   = 第 k 段是否属于有效工艺管线
```

硬约束示例：

```text
每个端点最多连接一个节点
某些已确认连接必须成立
明确断开的连接不能成立
泵入口不能连接到泵出口
阀门不能凭空成为流体源
```

目标函数可以是：

```text
最大化：
    观察证据得分
  + 几何连续性得分
  + 设备端口匹配得分
  + 工艺可行性得分
  - 假设数量惩罚
  - 断裂/跳跃连接惩罚
  - 与观察冲突的惩罚
```

但要注意：优化器只能找“在你给定假设下最合理”的解，不代表它是真实拓扑。

### 第四层：枚举多个候选解

不要只输出 top-1。输出：

- 最优候选；
- 次优候选；
- 每个候选的差异；
- 哪些连接决定了候选之间的分叉；
- 哪些观察可以区分它们。

这可以用：

- k-best solutions；
- 加入“排除上一解”的约束反复求解；
- beam search；
- MCMC/随机采样；
- 约束图上的 backtracking。

如果候选解很多，重点不是继续算，而是找**信息增益最高的观察点**：例如确认某个端点到底连到哪一支，可能一次就排除几百个候选。

## 3. 图算法可以做什么

纯图算法适合：

- 连通分量分析；
- 找盲端、环路、悬空支路；
- 检测孤立设备；
- 检测不可能的端口度数；

### 为什么是 NP-hard

如果问题包含：

- 多个端点的连接选择；
- 一个设备端口只能接一条或有限条管线；
- 可选的旁路、回流、假管；
- 环路与断点判断；
- 三个人观察记录之间的冲突；
- 在多个候选拓扑中选“最合理”的一个；

它就接近带约束的图匹配、子图同构、网络设计或整数规划问题。某些受限版本可以多项式求解，但加入候选连接、设备约束和真假管判断后，通常就是 NP-hard 或至少具有指数级最坏情况。

### 但“NP-hard”不等于你们算不动

你们的规模如果只是：

- 几十个设备；
- 几十到几百个端点；
- 每个端点只有少量空间上合理的候选连接；
- 大部分连接已经被观察确认；

CP-SAT、MILP 或回溯加剪枝通常能算。真正决定难度的不是“设备价值几百万”，而是：

```text
变量数量 × 每个变量的候选数 × 约束松紧程度
```

例如：

- 30 个端点，每个 3 个候选：通常很轻；
- 100 个端点，每个 20 个候选：可能迅速膨胀；
- 大量候选都同样合理、约束又弱：求解器能找到解，但很难证明唯一或最优。

### 更大的问题：可能根本没有唯一解

如果现场没有提供足够信息，算法面对的不是“一个复杂但确定的答案”，而是：

\[
\mathcal{S}=\{G_1,G_2,\ldots,G_k\}
\]

其中很多拓扑都符合目前的观测。

这时会出现三种情况：

1. **唯一可行解**  
   约束足够强，只有一个拓扑满足条件。

2. **多个可行解，但最优解明显领先**  
   可以报告 top-1，但必须说明评分模型和不确定性。

3. **大量近似等价解**  
   算法无法合理选出唯一答案。继续增加算力没有帮助，只会更快地列出一堆同样可能的答案。

尤其是以下情况会导致多解：

- 管线两端不可见；
- 假管和真管外观相同；
- 没有流向、物料或设备编号；
- 只有局部片段，没有统一空间坐标；
- 设备端口功能不明；
- 展示模型故意违反真实工艺规律；
- 三个人的记录之间存在未解决的冲突。

### 你们应该检查“是否唯一”，而不是只求一个答案

求解后至少做三件事：

#### 1. 统计可行解数量或找多个解

不要只运行一次优化器。每得到一个解，就加入排除约束，再找下一个：

```text
至少有一条边与上一解不同
```

重复寻找前 10 个或前 100 个候选解。

#### 2. 看边的出现频率

对多个候选解统计：

```text
某连接出现在 100% 的解中 → 稳定连接
某连接出现在 52% 的解中 → 高度不确定
某连接从不出现 → 可排除或被约束淘汰
```

这比只看一张最优图有用得多。

#### 3. 做约束敏感性分析

逐个取消或降低某条观察证据的权重，看答案是否大幅变化：

- 如果去掉一条低置信度观察，拓扑就完全变样，说明系统不稳；
- 如果多个不同拓扑得分几乎相同，说明现有信息不足；
- 如果所有候选都共享某些主干连接，那些部分可以较有把握地写入报告。

### 复杂度和“信息不足”要区分

可能出现：

- **计算难，但有唯一解**：需要好的求解器、剪枝和建模；
- **计算很容易，但有一万个解**：不是算力问题，是证据不足；
- **模型本身错误**：求解器返回唯一答案，但答案只是错误约束下的产物。

你们的场景很可能是第二种，或者“第二种为主、第一种为辅”。

### 实际建议

先做一个小规模原型：

1. 手工录入 10～20 个节点；
2. 生成空间上合理的候选边；
3. 加入硬约束；
4. 用 OR-Tools 找前 20 个解；
5. 比较它们的目标函数值；
6. 看有多少条边在所有解中稳定出现。

如果很快得到大量相近解，就不要继续加云算力，而应把结论写成：

> 在当前观测和约束下，存在多个同样可行的候选拓扑，无法唯一确定完整连接关系。算法输出的是候选集合，而非经过现场验证的唯一结构。

所以答案是：

- **是，完整问题通常具有 NP-hard 性质；**
- **小规模、强约束的实例大概率算得动；**
- **你们更可能遇到“多解不唯一”，而不是单纯算不动；**
- **GPU 基本不是关键，CP-SAT/MILP/回溯剪枝主要依赖 CPU 和建模质量；**
- **如果输入信息不足，任何算法都不能保证收敛到真实的单一拓扑。**

### 2.2 约束求解器（用你的笔记本跑）

**推荐：OR-Tools CP-SAT** + 自定义评分函数。

```python
from ortools.sat.python import cp_model

model = cp_model.CpModel()

# 变量：每条候选边是否连接
edge_vars = {}
for (i, j) in candidate_edges:
    edge_vars[(i, j)] = model.NewBoolVar(f"edge_{i}_{j}")

# 约束：每个端点最多连一个
for endpoint in all_endpoints:
    model.Add(sum(edge_vars[(endpoint, j)] for j in candidates[endpoint]) <= 1)

# 目标：最大化证据分数
objective_terms = []
for (i, j), var in edge_vars.items():
    score = compute_score(i, j)  # 根据观察置信度、空间距离、设备兼容性计算
    objective_terms.append(score * var)

model.Maximize(sum(objective_terms))
```
